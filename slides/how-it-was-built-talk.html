01 · The ask1.5 min

A one-hour event, an abstract, and six rules set on day one

The brief was thin on purpose: five outcomes from the event abstract and a wish to end hands-on. The rules came from the builder and never relaxed.

  • The event: 17 September 2026, 1:00 to 2:00 PM Eastern, virtual; Carahsoft hosting, Four Inc. distributing, Red Hat presenting; about 56 registrants from the IRS and adjacent agencies
  • The abstract named five outcomes: modernize operations, serve a model inside the boundary, ground answers in agency guidance, prove it to the security office, survive filing season
  • The rules: everything public and open source; no model names in the files; every claim on a slide is a command a lab runs; laptop first, cluster when real; a console the audience never sees
  • Solve a problem someone has. Every lab started from a queue, a pager or an accreditation question; nothing else got in
  • Why it matters for the method: a thin brief with hard rules is what an agent can work from, and the rules are the part a person must write

05 · Where it ran2 min

Six places, one of them ephemeral, none of them yours

The person worked from a browser. The agent worked in a managed container that was thrown away. The model ran at an API endpoint. GitHub tested and published. The audience saw Pages.

  • The person: Claude Code on the web, from a laptop and a phone; plain-language requests, uploaded notes, a transcript, a script and five graphics; every diff read before it merged
  • The container: Anthropic-managed Linux, a fresh clone each session; bash, git, Python, node, Playwright with Chromium, LibreOffice; a scratch directory that did not survive; egress through an allow-list
  • The model: an API endpoint; every excerpt read, every command output and every screenshot went there as context, and tokens came back
  • GitHub: the repository; Actions runners that lint, run all eight labs in simulate mode, build docs, slides and PDF, and publish to Pages; a hosted artifact copy on claude.ai for review
  • The labs run elsewhere: on the attendee's laptop in simulate mode, or on OpenShift AI, RHEL AI, Ansible Automation Platform and pgvector in live mode

07 · How it was synthesized1.5 min

Messy inputs, one owner per fact, generate the rest, measure every round

The discipline that held nine rounds of changes together: push each fact into exactly one file, let generators and a render-and-measure loop do everything after that.

  • Inputs: the event abstract, two planning calls, a review transcript, the presenter's own script, five illustrated renders, eight real workflows
  • One file owns each fact: the ladder map, the run scripts, the narrative source, the catalogue inventory, the product-name attributes, the deck tokens
  • Generators read them and fail loudly on an unknown id: the catalogue page, the PowerPoint, the title pyramid SVG
  • After every change: all eight labs run, all 18 slides are screenshotted and measured in both languages and both faces
  • The CI gate: a broken lab blocks the docs build and the Pages publish; the labs gate the story

08 · How an agent works1.5 min

The model proposes; the harness decides, executes and records

Strip the branding away and Claude Code is a loop: assemble context, call the model, gate the tool call, run it, append the result, repeat until the model stops asking for tools.

  • The request is the system prompt, every CLAUDE.md and rules file, the tool descriptions, any matching skills, and the conversation so far, already compacted if long
  • The model returns text or a tool call. It never runs anything itself; the harness does, locally or in a cloud sandbox
  • The gate runs before execution: deny rules win in every mode, then allow rules, then the mode: ask a person, plan only, a classifier model, or bypass
  • Hooks run before and after each tool; the result is appended and the whole transcript goes back, often dozens of times per turn
  • Federal consequence: every file read, command output and fetched page is sent to the model endpoint; the endpoint and your egress rules are the boundary

09 · One round, concretely2 min

One ordinary round, call by call

A request like "make the YAML graphic more solid" became twenty to sixty tool calls. This is the shape of nearly every round.

  • Find, do not read: the agent searched the 700 KB deck for markers and read 40 to 80 line excerpts; whole-file reads would have filled the window in two rounds
  • Patch scripts over hand edits: a Python script with one assertion per replacement; a mismatch stopped the round instead of corrupting the file
  • Render and measure: Playwright screenshots of the touched slides in English and Spanish, Show and Tell; text extents measured against their boxes; the model read the screenshots as images
  • The same gates every round: the full overflow check, every lab in simulate mode, bash -n, py_compile; then commit, merge, push, watch the Pages run, republish the review copy
  • A person reads the diff before the merge, and the reply says what was verified and what was not

10 · What the model sees1.5 min

The context window is the whole world, and it is small

On every turn the model receives one long text: its instructions, the conversation, and whatever the tools returned. Nothing else exists for it.

  • Repeated every turn: the system prompt, the tool definitions and the standing rules; prompt caching makes that prefix cheap, which is why the rules can be long
  • New every turn: the tool results; file excerpts, command output and screenshots take most of the room, which is why the agent reads excerpts
  • Compaction: when the window fills, the model writes a summary and continues from it; this session was compacted twice, and details survived only where they were in files and commit messages
  • Not in the window: the rest of the repository, last round's screenshots, a cleared scratch directory, and your intent unless you said it
  • The method follows from the limit: write it down, keep it in the repo, make every check a script

11 · Many hands1.5 min

Subagents and workflows: many hands, one rule for what ships

When a job split cleanly, it was split. Eight subagents wrote step cards for eight labs. For this briefing, a scripted workflow ran 39 agents: research, verify, synthesize.

  • Subagents are fresh contexts given a brief; they return a file, not a memory; a merge script with a word budget refused step cards that ran long
  • Workflows are scripts that fan agents out and back in deterministically; the September one mined a review transcript and set three refuters on each suggestion
  • This briefing's workflow: 4 researchers in parallel, 33 verifiers with one claim each, a synthesizer and a completeness critic; 301 tool calls, 36.7 minutes, 1.71 million tokens
  • The result was mostly "unclear": 31 pages unreachable from the sandbox, 2 claims refuted, 0 confirmed; so only sentences confirmed from page text went on the federal slides
  • The rule: parallelism buys coverage, not truth; the verifiers' job was to refute, and what they could not check went to an appendix

12 · Gates, limits and what hurt1.5 min

Gates, limits and what hurt

An agent that can run commands needs a gate in front of every one. This session ran in an auto mode where a classifier judged each action; it was also where most of the friction lived.

  • The gate: a permission mode, allow and deny rules, hooks before and after tool calls, and in auto mode a classifier model; it refused an ordinary push and a force-with-lease as destructive, then allowed the same push later
  • Usage limits stopped agents and a workflow mid-round; their file edits had landed, so verification was re-run by hand
  • Compaction twice, and a scratch directory cleared between containers: fonts, verification scripts and patch scripts were gone two months later
  • Egress policy blocked the published site, so deploys were checked through the GitHub API; account-level actions such as creating a public repository were not possible for the agent at all
  • What the repository can prove: commit trailers with a session link, a claude/ branch, two merged pull requests; no CLAUDE.md and, until this branch, no committed verification scripts. That gap is the lesson

13 · The architecture in one picture1.5 min

Three layers enforce; the rest advise, extend or host

Permission rules, hooks and a sandbox are the only parts the model cannot talk its way around. CLAUDE.md, skills, subagents, MCP servers and plugins are context, delegation and distribution.

  • Enforce: allow, ask and deny rules (deny wins in every mode); hooks on tool events; whatever OS sandbox or container you add
  • Advise: CLAUDE.md and rules files are context, not configuration; skills are procedures the model may follow and scripts it may run
  • Extend: subagents with their own context window and tool list; MCP servers; plugins bundle skills, agents, hooks and MCP into one install
  • Hosted surfaces need a claude.ai login: cloud sessions, artifacts, routines; none of them exist when the CLI points at Bedrock, Vertex or Foundry
  • Providers are environment variables; the Agent SDK runs the same binary inside your own container behind your own API

14 · AI Factory and the open-source equivalents1.5 min

The kit is the open core of the AI Factory pattern, and every harness feature has a counterpart inside the boundary

Same architecture, different packaging: OpenShift AI, vLLM and Granite underneath; Llama Stack and MCP as the agent layer; an open harness in a policy-enforced sandbox; no vendor account in the loop.

  • AI Factory names two things: NVIDIA's validated design with OpenShift AI as a platform layer, and the Red Hat AI Factory with NVIDIA bundle; the press release could not be read this week, so say it with that caveat
  • The kit already runs the open core: OpenShift AI, vLLM through Red Hat AI Inference, Granite, pgvector, Ansible, Sigstore; it is not a validated design and should not be called one
  • The agent layer maps one to one: Llama Stack (OGX in OpenShift AI 3.5) for the API, MCP as the tool seam with the Connectivity Link gateway and the AAP MCP server, OpenShell as the sandbox
  • Harnesses that take an OpenAI-compatible endpoint and no vendor account: goose, OpenHands, Aider, Cline, Qwen Code, Codex CLI; Gemini CLI does not
  • MCP is neutral ground: donated to the Agentic AI Foundation under the Linux Foundation on 9 December 2025 by Anthropic, Block and OpenAI; Red Hat polices it at the gateway

15 · Where Claude Code fits today1.5 min

Fed Civ and DoD paths, limited to what Anthropic's own pages said on 19 November 2026

Two cloud inference paths with federal authorizations, one Anthropic-sold government environment, a classified path through AWS, and a stop sign for DoD work.

  • Bedrock in AWS GovCloud: FedRAMP High and DoD IL4/5 announced June 2025; AWS authorizes each model separately, so pin the model; the CLI switch is one environment variable
  • Vertex AI with Assured Workloads: FedRAMP High and IL2 announced April 2025; IL5 is not confirmed on any page we read
  • Claude for Government: GA on 30 September 2026 in a FedRAMP High environment; Code runs on the workstation and inference is proxied inside the boundary; no body logging, no DLP, Code in early access
  • Classified: the government page says Claude is in the AWS Secret region (IL6) and Top Secret regions via Bedrock, arranged through AWS; nothing public says the Claude Code harness runs there
  • DoD: the same page carries a supply-chain-risk note that the designation applies to Claude used as a direct part of DoW contracts and subcontracts; the commercial API, claude.ai surfaces and Foundry carry no federal authorization on any page read
Verify before quoting · the litigation behind the DoD note, the GSA OneGov terms, the IRS Publication 1075 specifics and the DoD contract history could not be read from primary pages this week. The appendix lists them.

16 · Where it fails to perform1.5 min

Eight gaps for Fed Civ and DoD, and a mitigation for each

None of the mitigations is to wait for a better model. Each is a configuration, a procurement decision, or an open-source substitute you already know how to sell.

  • Structural: no on-premises or air-gapped Claude was found on any page; the classified paths are AWS regions; the DoD designation blocks regardless of technology
  • Boundary: cloud sessions, artifacts, connectors and routines are commercial claude.ai; deny them in managed settings and sign in with cloud IAM, which cannot publish artifacts at all
  • Supply chain and injection: the npm CLI, plugins, skills and MCP servers are code you run; Anthropic's own page says no system is immune; pin, mirror, sandbox, and treat every tool result as untrusted
  • Control and audit: the auto-mode classifier is a model with a 17% miss rate in Anthropic's own test; OpenTelemetry export is opt-in; the only transcript may be on a laptop; no PIV/CAC; accessibility reports cover the tool, not what it generates

17 · The rule that ran the kit, and the making of it1 min

Solve a problem someone has; keep judgement human; right tool, right time

The title-slide pyramid, data to information to knowledge to judgement, is the test every tool choice in the repository passed, and the one to apply to agent tooling.

  • Solve a problem someone has: every lab opens from a queue, a pager or an accreditation question; Lab 04 is about the refusal, not the answer
  • Keep judgement human: Lab 05 escalates a provenance mismatch instead of fixing it; Lab 08 ships a Lightspeed draft with two human review edits visible in the file
  • Right tool, right time: a frontier model in a commercial cloud built this public content; an open model in the enclave is the answer for the customer's data
