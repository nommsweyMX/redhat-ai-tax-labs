The through-line for the entire hour

AI increases the volume and velocity of information. Automation turns governed decisions into repeatable action. If the enterprise cannot deploy, test, approve, observe, audit and roll back ordinary change consistently, adding AI creates a faster queue of recommendations—not an operating capability.

  • Toolchain: shared inventory, source control, reusable content, testing, credentials, RBAC, approvals, observability, evidence and rollback.
  • Islands: scattered scripts and team-specific bots. Useful locally, but not institutional automation.
  • Institutional automation: reflexive rather than merely reactive—the estate senses a known condition, applies policy, executes a pre-approved response, validates it and records the result.

For the text-generating LLMs discussed here, training learns relationships in language; generation commonly builds a response one token at a time using the context available. That mechanism supports useful capabilities but does not guarantee factual truth. IBM’s LLM explanation.

Retrieval adds external passages to the material used for a response without having to retrain the model for each document change. It improves access to relevant evidence; it does not eliminate incorrect interpretation. IBM’s RAG explanation.

The distinction behind “it is a guess”

A model output is an estimate or generated response, not an authoritative ruling. “An educated guess” is a useful introduction, provided we explain what is being estimated. A predictive model estimates an outcome or category from learned relationships. A generative language model estimates suitable continuations of the response and constructs text. Neither automatically verifies the truth or legal applicability of every statement it produces.

This does not mean every answer is random or false. Models can learn useful facts and relationships and can answer correctly. It means their output needs evidence appropriate to the job. A retrieved document is a source record. A calculator result is the result of particular inputs and implemented rules. A prediction is an estimate. A generated explanation is a draft. Those are different things even when the same chat window displays them.

For the IRS example: training on IRS documents does not turn model weights into a controlled, current policy repository. A model can reproduce an old rule, combine two rules incorrectly, overlook an exception or apply the right guidance to the wrong facts. The relevant authority comes from the applicable law and approved guidance or procedures, with the right version and case context. This presentation illustrates system design; it supplies no deduction thresholds or actual eligibility ruling.

Useful spoken line: “The model can help us find and explain the rule. It does not get to invent the rule. Confidence in the wording is not proof that the rule applies.”

SLIDE 02 · AI IN PLAIN ENGLISH

Four different jobs get called “AI”

3–11 min block begins
InformationKnowledgeJudgement
On screenFour cards — Predictive (estimate), Generative/LLM (create), Agentic (reason + act), Automation (execute) — with analogies, and a dashed "what it is not" box.

Terminology comes first, by design — foundational context before any argument. Federal audiences hear "AI" used as if every technique is the same, and as if AI means the consumer tools — Claude, ChatGPT, Gemini, Copilot. It is neither. Predictive AI estimates. Generative AI creates. An LLM is a generative model specialized in language. Agentic systems add tools and rules. Automation executes known steps.

Walk the analogies — the weather forecast, the well-read drafting assistant, the junior analyst with a restricted tool belt, the checklist that performs the checklist (that is where Ansible belongs). The strongest mission pattern combines them; the categories are layers in a governed workflow, not four competing products.

Predictive AI · estimates

Finds a pattern in historical or streaming data and returns a score, class, probability or forecast. It answers: what is likely?

Generative AI / LLM · creates

Produces new text, code or summaries. An LLM is simply a generative model specialized in language. It answers: how can we express or synthesize this?

Agentic system · uses tools under rules

Adds a controlled tool belt and a policy envelope: allowed data, permitted actions, approval gates, stop conditions and evidence requirements. It answers: what should I inspect or invoke next?

Automation · executes known steps

Runs a tested, versioned procedure consistently and records the result. It does not invent policy or make the accountable determination. It answers: how do we perform what was already decided?

Example 1 · System administrator troubleshooting an out-of-memory event

PredictTelemetry estimates that memory exhaustion is imminent or classifies the current failure as the recurring OOM pattern.
GenerateThe LLM turns logs, metrics, changes and cited runbooks into a concise diagnosis and recommended next checks.
Agent + tools/rulesTools: log search, metrics, CMDB, ITSM and an Ansible dry run. Rules: read-only first; allowlisted systems and playbooks; threshold and maintenance-window checks; approval for disruptive change; retain evidence; stop on ambiguity.
AutomateA tested playbook opens the ticket, captures state, performs the approved remediation, validates service health, rolls back on failure and closes the record.

Example 2 · Auditor checking whether claimed deductions reconcile

PredictA model flags an unusual deduction pattern or estimates mismatch risk. That score prioritizes review; it is not a tax determination.
GenerateThe LLM summarizes the return, substantiation and cited guidance, and drafts the questions a reviewer should resolve.
Agent + tools/rulesTools: the filing entity’s approved online calculator, authoritative rules lookup, transcript/document retrieval and the case system. Rules: use only the approved calculator and current tax-year rules; never alter source values; keep data inside the boundary; capture every input, result and citation; route mismatches to a person.
AutomateThe workflow extracts approved fields, validates them, submits the calculation, attaches the result and evidence, and routes exceptions. The auditor still decides whether the deduction is appropriate.

Mistake #1 · Starting AI before enterprise automation is mature

AI creates more observations, summaries, recommendations and potential actions, faster than people can absorb them. Without a program-wide automation toolchain, that output becomes ticket growth, manual queues and inconsistent changes. A few scripts, RPA bots or team-specific playbooks are islands of automation; they are not a toolchain and they are not institutional capability.

  • Reactive: a person notices, interprets, approves, starts and later documents every response.
  • Reflexive: the institution detects a known condition, applies encoded policy, executes a pre-approved response, validates it and preserves the audit trail—while escalating anything outside the envelope.

Discussion · what “not IRS policy” actually means

The model is not empty of facts. Training can encode information about tax rules, notice language and procedures. The problem is that those learned patterns are not a version-controlled copy of the applicable authority, and an answer does not come with an automatic guarantee that the right rule was selected.

An LLM can generate a convincing sentence about a deduction because it has seen similar language. That sentence might reflect an older year, omit a condition or blend two different situations. A predictive model can flag an unusual amount because it resembles past anomalies. That resemblance does not establish whether a rule permits the amount. Neither system becomes the policy owner through training.

Three sources of an answer:

  1. Learned information: what the model picked up during training. Useful but potentially stale, incomplete or difficult to trace to a source.
  2. Retrieved information: the actual passages supplied for this response. Their version, access permissions and applicability matter.
  3. Tool results: an observed system state, calculation or database record returned by a tool. These have their own inputs, timestamps and possible errors.

A good response distinguishes those sources. “I observed this in the log,” “I estimate this from the pattern,” and “the approved runbook says this” are materially different claims.

Prompting, retrieval and fine-tuning: better instructions help when the task is unclear; better retrieval helps when the needed evidence is missing; additional training may help when the model consistently performs a specialized task poorly. These approaches can be combined, but there is no rule that using all three always gives the best result.

Discussion · a forecast, an explanation and a formula are different

Discussion · reflexive institutional automation in plain language
