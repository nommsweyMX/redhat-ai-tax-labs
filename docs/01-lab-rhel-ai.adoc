= Lab 01 — Serve a model inside your boundary

[cols="1,3"]
|===
| Product   | {rhaiis}
| Time      | About 5 minutes
| Script    | `labs/lab01-rhel-ai/run.sh`
| Outcome   | A supported LLM classifying taxpayer contacts on hardware you control
|===

== Objective

Bring up a large language model on a single GPU host and use it to classify a
real taxpayer inquiry — with no inference call leaving the machine.

This lab exists to answer one question directly, because it is the question
that decides whether anything else in this guide is relevant to a tax agency:
*where does our data go when someone prompts the model?*

The serving engine is the {rhaiis}: the vLLM engine, packaged and supported as
a signed container that runs anywhere {rhel} runs. (Earlier versions of this
lab used the retired InstructLab `ilab` CLI; the endpoint it exposes — an
OpenAI-compatible API on localhost — is unchanged.)

== Prerequisites

For `LAB_MODE=simulate`, nothing. For `LAB_MODE=live`:

* A {rhel} host with a supported accelerator and the container toolkit's CDI
  devices generated (`nvidia-ctk cdi generate`)
* `podman` and `huggingface-cli` on the path
* Registry credentials for `registry.redhat.io`
* Roughly 20 GB of free disk for the model

[source,bash]
----
cd labs/lab01-rhel-ai
LAB_PACE=step ./run.sh
----

== Walkthrough

[cols="1,2,3", options="header"]
|===
| Step | Command | What to look for

| 1
| `podman pull registry.redhat.io/rhaiis/...`
| The signature check on the way in. The serving engine is signed content,
  patched and lifecycled like any other RHEL container.

| 2
| `huggingface-cli download RedHatAI/...`
| A validated model from the Red Hat AI repository, landing on local disk.
  For an enclave, mirror it into your own registry instead — Lab 06 verifies
  the signature.

| 3
| `podman run ... -p 127.0.0.1:8000:8000 ...`
| The vLLM engine starting and the port publication. In production this is a
  Quadlet-managed systemd unit, not a foreground process.

| 4
| `ss -ltnp \| grep :8000`
| *The point of the lab.* The endpoint is published on `127.0.0.1`. There is
  no egress path from this process to a public model API.

| 5
| `curl .../v1/chat/completions`
| A structured classification with a routing queue, the missing form, and a
  draft reply written for a human to edit and sign.
|===

== What good looks like

The model returns a category, a routing queue, the missing document and a draft
reply. It does *not* state a determination as final — that behaviour comes from
the system prompt in `assets/inquiry.json`, which is worth reading before you
change it.

Latency on a single H100 for an 8B model at this prompt length lands under two
seconds. If yours is much slower, check that the model actually loaded onto the
accelerator rather than falling back to CPU.

== Troubleshooting

`Error: setting up CDI devices: unresolvable CDI devices nvidia.com/gpu`::
The container toolkit has not generated CDI specs on this host. Run
`nvidia-ctk cdi generate --output=/etc/cdi/nvidia.yaml` and retry.

Pull fails with an authentication error::
Run `podman login registry.redhat.io` first. The lab does not handle
credentials, deliberately.

The model loads but inference is slow::
Check `nvidia-smi` during a request. If GPU utilization stays near zero, the
runtime fell back to CPU — usually a driver or container toolkit mismatch.

Port 8000 already in use::
Another serving process is running. `ss -ltnp` will name it.
