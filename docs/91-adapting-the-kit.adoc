== Adapting the kit: modify the deck and the labs for your own use case

This chapter is for the account solution architect who has to take this kit to a different room: another agency, another mission, another presenter, or a use case the eight labs do not yet prove. It names the file that owns each fact, the files that copy it by hand, the generators that must be re-run, the gates that stop a broken change, and eight recipes (R1 to R8) that were executed in scratch clones of this repository at commit e877414 and corrected against what the files actually contain. The checks were re-run at 2ee707f, the head of `all-in-one-preso` when this chapter was written, which differs from e877414 only in bin/build-brief.py below line 1189 and in docs/96. Line numbers are for that tree; after your first insertion into a file, find things by the markers quoted here, not by number.

=== How the kit is organized for change

.The extension points: for each area, the file that owns it and what you change there
image::built/knobs.png[The extension points, pdfwidth=100%]

*Sources of truth.* Each fact has one owner file; everything else is a copy.

* `labs/labNN-<name>/run.sh` owns what a lab does. A lab is a linear list of `step "<command>" <<'OUT' ... OUT` calls on the runtime in `bin/lib.sh`: simulate mode prints the heredoc, live mode `eval`s the command in the lab directory and prints the heredoc only when the command exits non-zero (bin/lib.sh:92-106). The header says it plainly: "The simulated output is not decoration: it is the acceptance criterion" (bin/lib.sh:11-12). Discovery is the glob `labs/lab*/run.sh` in bin/run-all-labs.sh:11, which `cd`s into each directory first (:14). Nothing registers a lab.
* `docs/0N-lab-<name>.adoc` owns the written walkthrough: `[#lab-0N]` anchor, a five-row header table (Product, Rung, Time, Script, Outcome), Objective, Prerequisites, a Walkthrough table with one row per step, What good looks like, Troubleshooting, Discussion questions (docs/07-lab-ops-notebook.adoc:1-13, 45, 57, 89, 113, 128). docs/index.adoc pulls chapters in between `:leveloffset: +1` (:193) and `:leveloffset: -1` (:221); product names come from docs/attributes.adoc:15-20 (`{rhel}`, `{rhaiis}`, `{ocp}`, `{rhoai}`, `{aap}`, `{eda}`), which reach only the AsciiDoc book.
* `slides/deck.html` owns the interactive deck, and it has no build step: 4,947 lines, about 753 KB, one `<article class="slide" data-title=... data-rungs=... data-notes=...>` per slide (18 of them, from line 940 to 1870). Everything else is derived at load time from DOM order (`var slides = ...querySelectorAll('.slide')`, 1995) or keyed on `data-title`: `CHAPTERS` (2096), `TITLES_ES` (2558), `SLIDE_GFX` (2181), 103 CSS selector occurrences on 87 lines. The Labs view is `var LABS = [` (3226 to 3937, 42 `cmd:` entries) and `var LAB_CARDS = [` (3948 to 4265, 42 step cards plus 8 wrap cards); Spanish is `var ES_TEXT = {` (2577, 605 entries) applied by `setLang` (4869) over `I18N_SEL` (4856).
* `slides/presenter-notes.html` owns the presenter console: 26 `<section class="step">` in deck order, `var SLIDE_N = 18` (1755), lab steps derived as `steps.length - SLIDE_N` (1756), and jump buttons whose `data-goto` values are absolute 0-based step indices (1121, 1258, 1593, 1680, 1681).
* `slides/slides.adoc` (18 `==` slides, 18 `[.notes]` blocks) and `bin/build-pptx.py` (`DECK_RUNGS` keyed by data-title at 156, `add_spine` indexing it at 248, eleven hand-coded slide blocks, default output at 1145) are two more hand-written copies of the narrative.
* `slides/ladder-map.json` declares itself the single source of truth for rung tagging and says the deck, console, slides.adoc, docs and README must agree with it (line 2). Only bin/build-adventure.py reads it (:104), and only its `rungs` and `technologies`. The chip vocabulary is `labs[].chip` (:289-360) plus the four `rungs` keys.
* `bin/adventure-inventory.json` (57 items) owns the catalogue page. bin/build-adventure.py sorts labs and slides by id and derives their number from the id suffix (:107-115), links `./#lab-N` (:121), hard-codes `./#slide-18` (:131) and `./#slide-6` (:456), aborts on an unknown id in a reading path (:244), and renders guide cards from a hard-coded id list (:316).

*Generators.* Four `make` targets rebuild committed outputs: `make adventure` writes slides/adventure.html (Makefile:64-65); `make pptx` writes slides/exports/redhat-ai-tax-administration.pptx with python-pptx (:61-62); `make brief` writes the three how-it-was-built pages and docs/96 (:67-70), and the CI test job regenerates and `cmp`s them (docs.yml:43-51); `make graphics` renders the methods-page SVGs and PNGs with Node Playwright (:75-77). `node bin/regen-title-pyramid.js` rewrites the title slide's pyramid SVG from the deck's own function (R5). Nothing generates slides/deck.html, slides/presenter-notes.html or slides/slides.adoc from anything else.

*Gates.* `make lint` runs `bash -n` over bin/*.sh and labs/*/run.sh and `py_compile` over a fixed list ending `labs/lab04-rag/*.py` (Makefile:79-84, list at :83); `make test` adds every lab in simulate mode with `LAB_SPEED=0 NO_COLOR=1` (:89-90) and ends `All labs completed.` in under a second. CI runs the same test job (docs.yml:28-41), then the build job copies deck.html, presenter-notes.html, adventure.html and the exports verbatim (:76-84), and publishes only on push to `main` (:10, :94). A broken lab blocks the site. The book itself is rendered in CI without `--failure-level` (docs.yml:63), so a warning you do not catch locally publishes. `make docs` needs a running podman or docker daemon, not just the binary: Makefile:12 picks the runtime with `command -v` and `check-runtime` (:35-41) tests only that, so a docker binary with no daemon passes the check and fails at the container run with an unrelated error. To render the book without a container, with the user-installed gem (2.0.26 at the time of writing) and warnings treated as failures:

[source,bash]
----
A="$(ruby -e 'puts Gem.user_dir')/bin/asciidoctor"
[ -x "$A" ] || gem install --user-install --no-document asciidoctor
"$A" --failure-level WARN -D <scratch>/build -o index.html docs/index.adoc    # keep -D outside the repository
----

*The blast radius.* The commit that last added a lab and a slide together, `git show --stat 7dd52f2`, touched 18 files: README.adoc, bin/adventure-inventory.json, bin/build-adventure.py, bin/build-pptx.py, bin/preflight.sh, docs/08-lab-grand-demo.adoc, docs/90-facilitator-guide.adoc, docs/index.adoc, four files under labs/lab08-grand-demo/, slides/adventure.html, slides/deck.html, the .pptx export, slides/ladder-map.json, slides/presenter-notes.html and slides/slides.adoc. Use that list as the checklist for any change of the same kind.

*Standing rules.* They apply to every recipe below.

. Public and open source only. No customer records, logs, hostnames, non-public guidance, named individuals or registrant counts enter a tracked file. Sample content is illustrative and says so (README.adoc:212-223). Customer corpora stay out the way labs/lab04-rag/corpus/ does (.gitignore:11-13).
. No model names in files. Commands use the kit's variables (`+$MODEL_REPO+`, `+$MODEL_PATH+`, `+$BASE_MODEL+`, `+$MODEL_REF+`); prose, product strings and heredocs say "the model" or a neutral artefact name. Do not use the `base-model` and `tuned-model` attributes (docs/attributes.adoc:24-25) in new prose: they render as model names. Several shipped files still carry one; do not copy them.
. Every claim a slide makes is something a lab prints in simulate mode and runs in live mode. The deck's `LABS` terminals are transcribed from run.sh, never the other way round.
. Labs run on a laptop with nothing installed (`make test`) and against a real environment with `LAB_MODE=live` and the `+VAR="${VAR:-default}"+` knobs at the top of each script.
. Judgement stays human. The ladder's top rung is "deliberately human; automation executes what was decided, it never decides" (slides/ladder-map.json, `rungs.judgement.definition`). The last step of every lab is a person's screen.

*Working rules.* Work in a clone (`git clone -q /home/user/redhat-ai-tax-labs <scratch>/adapt-<label>`), never in the shared checkout. Never reflow or reformat slides/deck.html: line 2151 is a 171,286-character base64 literal and the script is one IIFE (1990 to 4946). Edit by marker with `sed -n`, `grep -n` and anchored replacements that assert the anchor occurs once. Regenerate and commit every generated output alongside its source.

*Defects you inherit.* Known at e877414, so you do not debug them as your own mistakes: `LAB_PACE=step` never pauses, because `read -r key` at bin/lib.sh:64 reads the heredoc that `expected="$(cat)"` (:78) already consumed; the deck's terminals already diverge from run.sh in 46 places (Lab 04 has five steps in run.sh and four `cmd:` entries in the deck); "seven labs" survives on 18 deck lines, 9 console lines and 5 inventory lines although eight labs ship; the console's slide-17 heading still reads "Seven labs" (presenter-notes.html:1219); `CHROME.es.show` is defined twice (2529 and 2542) so the Spanish terminal button reads "Mostrar" while `wrongHint` says "Ver"; 42 `ES_TEXT` keys have no English source left; Lab 04 steps 4 and 5 exit 3 by design on a refusal (labs/lab04-rag/query.py:148, :156), which live mode counts as a failure; Labs 02, 07 and 08 call helper scripts that are not in the repository.

*The adaptation checks.* The repository had no check that its copies agree. Eight small scripts and one allowlist were written and run while these recipes were verified; they are committed beside the builders in `bin/`, and the Python ones are in the `py_compile` lists at Makefile:83 and docs.yml:35. `check-labs-parity.py` compares the deck's `LABS` with run.sh (commands with the knob defaults substituted, output lines with `note` lines excluded) and counts each lab's `LAB_CARDS` facets against its deck steps plus the wrap; `--lab NN` reports one lab, so a new lab is judged apart from the 46 divergence entries the eight shipped labs carry today (none of them from the cards). `check-es-keys.py` lists `ES_TEXT` keys with no English source (42 today). `check-agree.py` compares the deck articles with `CHAPTERS`, `TITLES_ES`, `SLIDE_GFX`, ladder-map, inventory, console, pptx, slides.adoc and docs (one FAIL today, the console heading at 1219). `check-markers.sh` greps old mission and event markers with the methods pages excluded (729 lines today with its built-in pattern, 784 with the mission regex the R1 Checks block adds). `check-chain.py` checks the slide chain after an add, remove or move (0 findings today). `deck-measure.js` renders every slide in both languages, faces and themes with Playwright (56 overflow lines today at 1280x800, 28 at 1920x1080). `check-i18n.js` and `check-i18n-static.py`, with the `bin/i18n-keep-english.txt` allowlist, measure translation coverage in a browser and from the text (0 missing, 6 unreachable, 63 stale and 1 duplicate today in the browser; the static one exits 1 on its 42 stale entries). The two browser checks need `npm i -g playwright` and a Chromium, and take `NODE_PATH` and `CHROMIUM` exactly as the R4 Checks block shows; bin/render-graphics.js:16 reads the same `CHROMIUM` variable. Run them before you edit, so you know which findings are yours.

=== R1. Retarget the deck and the labs to a different agency and mission

Use this when the shape fits (six chapters, the ladder, eighteen slides, eight labs) but the story does not. It keeps every `data-title`, `CHAPTERS` entry, rung, chapter and lab slot, so nothing positional moves. The worked example is a state department of revenue with a refund-review backlog. A names-and-faces-only pass (presenters, account executive, partners, date, site, logos) is R5.

=== The afternoon plan

.The lab brief, the time boxes and the gates

Four hours from a thirty-minute conversation to a lab that passes `make test`, with the docs chapter and the catalogue entry: brief 30 min; ladder and product 15; expected output 45; run.sh 45; gates 5; docs 30; registration and `make adventure` 25; review and commit 15.
