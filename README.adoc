= Red Hat AI for Intelligent Tax Administration
:toc: macro
:toclevels: 2
:icons: font
:experimental:

Presentation, hands-on labs and documentation for the Red Hat, Four Inc. and
Carahsoft virtual event on modernizing tax administration with AI and
automation.

Seven labs walk the whole path: standing a model up inside your boundary,
teaching it your agency's vocabulary, serving it through a filing-season peak,
grounding its answers in your published guidance, automating the operational
toil around it, proving the result to an authorizing official, and pointing
the same retrieval pattern at your own logs to drive MTTR down.

One theme runs through all of it: the ladder from data → information →
knowledge → judgement. Data is what happened; information is data in context
for one case; knowledge is the guidance, precedent and runbooks the institution
owns; judgement is a determination someone signs. Every lab and every
technology in the deck and the docs is tagged with the rung it serves, and
judgement stays human — automation executes what was decided, it never
decides.

Every command is real and copyable. Every lab runs in two modes — one that
needs nothing but a shell, and one that executes against your own environment.

The kit is published at https://nommsweymx.github.io/redhat-ai-tax-labs/ — the
interactive deck, with its Labs and Demo views, is the landing page. The
presenter console is at `/presenter-notes.html`, the documentation at
`/docs/`, the reveal.js deck at `/slides.html` and the PowerPoint export under
`/exports/`. Not sure where to start? `/adventure.html` is the
choose-your-own-adventure catalogue: six reading orders by job, every lab,
slide, guide and tool, and what a live run needs. Drop presenter photos at `slides/assets/brad-scalio.jpg` and
`slides/assets/jon-keam.jpg` and the contact slide picks them up.

== Quick start

[source,bash]
----
git clone https://github.com/nommsweyMX/redhat-ai-tax-labs.git
cd redhat-ai-tax-labs

# What can run live here, and what cannot
./bin/preflight.sh

# Walk one lab, pausing for Enter at each command
LAB_PACE=step ./labs/lab01-rhel-ai/run.sh

# Walk all seven end to end
./bin/run-all-labs.sh
----

Nothing above needs a cluster, a GPU, or credentials.

== Lab modes

`LAB_MODE=simulate`:: The default. Prints each command followed by the output
you should expect. Runs on any laptop. Use this during the event.

`LAB_MODE=live`:: Executes each command against your own environment. On a
non-zero exit the expected output stays on screen so you can see what should
have happened.

[cols="1,3,1", options="header"]
|===
| Variable | Meaning | Default

| `LAB_MODE`  | `simulate` or `live`                    | `simulate`
| `LAB_PACE`  | `auto`, or `step` to wait for kbd:[Enter] | `auto`
| `LAB_SPEED` | Seconds between simulated output lines  | `0.04`
| `NO_COLOR`  | Set to anything to disable ANSI colour  | unset
|===

WARNING: `LAB_MODE=live` runs real commands. Lab 03 includes a load test that
will consume every GPU its namespace can schedule. Lab 06 reads node
configuration over SSH. Point them at a non-production cluster first.

== Building the documentation and slides

Rendering AsciiDoc needs Asciidoctor. The Makefile uses the official container
image so you do not have to install Ruby.

[source,bash]
----
make docs      # docs/index.adoc  -> build/docs/index.html
make slides    # slides/slides.adoc -> build/slides.html (reveal.js)
make pptx      # slides/exports/redhat-ai-tax-administration.pptx
make adventure # slides/adventure.html from bin/adventure-inventory.json
make pdf       # build/redhat-ai-tax-administration.pdf
make test      # shell syntax check + run all labs in simulate mode
make all       # everything above
----

`make pptx` needs only Python and `python-pptx`. The GitHub Actions workflow in
`.github/workflows/docs.yml` builds the documentation and slides on every push
and publishes them to GitHub Pages, with the interactive deck as the landing
page: https://nommsweymx.github.io/redhat-ai-tax-labs/

== A note on the sample content

The notice families, publication references and taxonomy entries here are
illustrative examples written for the exercise. They are shaped like real
agency content so the labs feel real, but they are not authoritative guidance
and no agency has reviewed them. Replace them with your own published material
before generating training data or indexing a corpus.

The figures in the simulated output — latencies, replica counts, evaluation
scores — are representative of a working environment, not measurements from a
specific deployment. Treat them as the shape of a good result, and measure your
own.

== Contributing

Lab content changes belong in the lab script and its `docs/` module together —
they are read side by side and drift apart quickly otherwise.

Before opening a pull request:

[source,bash]
----
make test
----

That runs `bash -n` over every script and executes all seven labs in simulate
mode. CI runs the same thing.
